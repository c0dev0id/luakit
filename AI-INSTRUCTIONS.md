# AI Instructions for Preserving Public API and Documenting Changes

## Overview
This document provides guidelines to ensure that the public API of the project is preserved during the development process. It is crucial that any changes made do not break existing functionality or affect users relying on the API.

## Guidelines for Preserving the Public API
1. **Version Control:**  
   - Use semantic versioning for the API. Increment the major version when breaking changes are introduced, the minor version when new features are added in a backwards-compatible manner, and the patch version for backwards-compatible bug fixes.

2. **Deprecation Policy:**  
   - Introduce a deprecation policy where older API methods can be marked as deprecated instead of removed outright. Inform users about the upcoming removals and provide alternatives.

3. **Testing:**  
   - Write unit tests for all public methods. Ensure that tests cover not just positive cases, but also edge cases.
   - Utilize integration tests to ensure that the public API works seamlessly with other modules.

4. **Code Reviews:**  
   - Ensure that any changes made to the API go through a thorough code review process. Pay special attention to comments and documentation accompanying the API.

5. **Documentation:**  
   - Always update the API documentation with any changes made. Keep it clear, concise, and easily accessible.
   - Make use of tools like Swagger or API Blueprint for autogenerated documentation.

## Documenting Changes
- **Changelog:**  
  - Maintain a CHANGELOG.md file to keep a history of changes made to the API with clear descriptions of what was changed and why, including the version number.

- **Commit Messages:**  
  - Write meaningful commit messages that explain the intention behind changes, especially in regard to public APIs.

- **Pull Requests:**  
  - Clearly describe the changes in your pull request, and tag relevant team members for review.

## Conclusion
Following these guidelines will help maintain the stability and usability of our public API. Regularly revisiting and adhering to these practices will benefit the entire development team and our users.
